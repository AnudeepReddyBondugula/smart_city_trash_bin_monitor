# 🚮 Smart City Trash Bin Monitor 🏙️

The Smart City Trash Bin Monitor is a real-time data engineering project that simulates and processes IoT-enabled smart trash bin data. The system ingests live bin data (fill level, location, time), processes and stores it, and provides actionable insights.

This repository specifically focuses on the **Data Generation Service (BinForge)** which handles creating mock telemetry data and publishing it to Kafka.

## 🏗️ Architecture

- **Python & AsyncIO**: Simulates thousands of bins concurrently on a single thread.
- **PostgreSQL**: Serves as the master source of truth for the bins.
- **Apache Kafka**: The ingestion stream for all telemetry generated by the service.

## 🚀 Setup for Local Development

Follow these instructions to run the entire stack locally.

### 1. Requirements
Ensure you have the following installed:
- Python 3.11+
- Docker & docker-compose

### 2. Python Environment Setup
Navigate to the root directory and set up a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r binforge/requirements.txt
```

### 3. Environment Variables
The repository comes with a `binforge/.env.local.example` file. You must copy it to create your private `.env.local` file inside the `binforge` directory:

```bash
cd binforge
cp .env.local.example .env.local
cd ..
```
If you need to make changes to ports or credentials, modify the newly created `binforge/.env.local` file.

### 4. Start Infrastructure
Start the local PostgreSQL and Apache Kafka (KRaft mode) containers:

```bash
docker-compose -f docker-compose.infra.yml up -d
```
Wait a few seconds for PostgreSQL to become fully ready.

**Managing the Infrastructure:**
- **View Logs**: `docker-compose -f docker-compose.infra.yml logs -f`
- **Stop Containers**: `docker-compose -f docker-compose.infra.yml down`
- **Wipe Data (Hard Reset)**: `docker-compose -f docker-compose.infra.yml down -v` (This will delete the PostgreSQL database and Kafka topics, requiring you to re-run migrations and seeding).

### 5. Apply Database Migrations
We use Alembic to manage database schemas. Initialize the tables in PostgreSQL by running:

```bash
cd binforge
alembic upgrade head
```

### 6. Seed the Database
The simulation app reads from the database. To simulate bins, you must first insert them. We provide a seeding script that uses Faker:

```bash
# Still in the binforge/ directory
python scripts/seed.py --count 50
```
> **Tip:** You can run `python scripts/seed.py --count 50 --clear` if you want to wipe existing bins and start fresh.

### 7. Start the Simulator
Start the AsyncIO application. It will automatically read active bins from the database and start streaming telemetry to Kafka!

```bash
# From the binforge/ directory
./scripts/run_local.sh

# OR manually:
PYTHONPATH=. python src/main.py
```

## 🔍 Verification & Debugging

Once the application is running, you can manually verify that data is flowing correctly using these handy Docker commands.

### 1. View the Database (PostgreSQL)
To prove that the bins were seeded correctly, execute a SQL query directly inside the Postgres container:
```bash
docker exec -it smartbin_postgres psql -U postgres -d smart_city -c "SELECT bin_id, capacity, latitude, longitude, status FROM smart_bins LIMIT 10;"
```

### 2. View the Live Telemetry Stream (Kafka)
To verify the simulator is actively producing data, attach a console consumer to the Kafka topic. You should see real-time JSON payloads streaming in:
```bash
docker exec -it smartbin_kafka kafka-console-consumer --bootstrap-server localhost:9092 --topic smartbin-telemetry-v1
```
*(Press `Ctrl+C` to exit the stream)*
